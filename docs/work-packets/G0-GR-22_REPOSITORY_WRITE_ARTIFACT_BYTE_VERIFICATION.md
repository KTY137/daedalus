# G0-GR-22 — Repository-Write Artifact Byte Verification

## Exact parent and narrow role

This packet stacks directly on `g0/repository-write-evidence-index-v2-linear`
at `ba439552058d0135e190194c34cc556e71b1acca`. It verifies already-resolved
repository-write inventory bytes against the additive artifact contract and one
exact GateReport-v3. It does not resolve a locator, authenticate a signer or
trust bundle, inspect Git HEAD, modify the evidence index, issue a release
receipt, approve an owner action, promote, or merge.

## Strict byte and canonical inventory verification

`verify_repository_write_artifact(...)` accepts only exact
`RepositoryWriteArtifactEvidence`, exact `GateReportV3`, and exact immutable
`bytes`. Empty, mutable, view-backed, subclassed, or oversized byte subjects
refuse before hashing. The verifier then:

1. hashes the provided bytes and compares the digest with artifact evidence;
2. compares the artifact evidence with the exact GateReport-v3;
3. decodes strict UTF-8 JSON with duplicate-key and non-finite-value refusal;
4. requires the exact repository-write inventory-v2 root, component, and
   surface fields;
5. reconstructs exact `RepositoryWriteSurface` and
   `RepositoryWriteInventoryV2` values;
6. requires the parsed payload to equal the reconstructed canonical wire form;
7. compares source revision, inventory digest, scan-input digest, file count,
   canonical failure-set digest, and failure count with retained evidence.

The parser therefore does not trust declared `closed`, blocker counts, scanner
flags, component digests, or the declared inventory digest. They must all be the
values regenerated by the canonical inventory-v2 model.

## Verification receipt

A successful comparison produces a canonical
`RepositoryWriteArtifactVerificationReceipt`. It binds the source revision and
retained source-tree revision, GateReport-v3 digest, artifact-evidence contract
digest, independently computed artifact-content digest, reconstructed inventory
digest, exact verification time, and a fixed ordered check set. Exact
`ContractProvenance` must bind every verified digest. The accompanying JSON
Schema mirrors the exact receipt wire shape and fixed check sequence.

The receipt proves only the supplied byte/report/evidence tuple. It does not
prove that a trusted resolver obtained the bytes at the retained locator, that a
trusted signer produced them, or that the retained source-tree revision equals
current authenticated Git HEAD.

## Prepared adversarial verification

Behavior tests cover successful receipt round trip, byte substitution, exact
artifact/report/bytes/provenance containers, empty and oversized content,
malformed UTF-8/JSON/non-finite values, duplicate keys, extra and missing wire
shape, wrong scalar domains, malformed revisions and paths, unsorted and
duplicate surfaces, derived-field and digest substitution, report/artifact
substitution, failure-set and failure-count binding, and receipt tampering.

A separate AST/source review checks the absence of locator, network, process,
filesystem-write, effect, release, approval, and promotion authority. It also
checks that exact subject and byte validation occurs before hashing and that all
artifact/inventory/report comparisons remain in the verifier. Thirteen bounded
mutants attack exact types, byte bounds, content hashing, report binding,
canonical payload equality, inventory/scan/file/failure comparisons, and the
fixed receipt check set.

CI requests two hash seeds on Ubuntu and Windows with Python 3.10 and 3.12,
focused tests, the mutation campaign, predecessor artifact/report regressions,
the full suite, package build, and isolated-wheel import.

## Remaining trust and release boundary

This packet does not close issue #194. A later authenticated resolver and trust
bundle must prove where the bytes came from, verify the signing authority, bind
the receipt into the evidence index, and compare the retained source-tree
revision with exact current Git HEAD/tree evidence. The current
`Gate0ReleaseReceipt` remains on the older evidence contract.

The repository-write inventory is still discovery evidence. Gate 0 cannot close
until every retained production write surface is canonically registered,
guarded, fault-tested, and proven unable to mutate the Primary Checkout. Issue
#189's provider-observation SQLite and filesystem paths remain open.

No source inspection or LLM statement is hard evidence. Exact-head execution
remains unavailable while GitHub Actions issue #67 terminates jobs before Step 1
without logs or artifacts. No automatic merge, promotion, OwnerApproval,
PromotionReceipt, or Gate transition is authorized.
