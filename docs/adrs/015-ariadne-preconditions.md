# ADR-015: Ariadne Preconditions

## Status

Proposed. **Recommendation: do not build Ariadne yet.** This ADR is a blocking
gate in front of ADR-009; it does not withdraw the name or the design, it states
what must be measurable before the engine is worth writing.

Every number below carries its provenance: **MEASURED** (re-run for this ADR on
2026-07-29), **INHERITED** (quoted from an earlier record, not re-run here), or
**ASSUMED** (reasoned, not measured — flagged as such).

## Context

ADR-009 names **Ariadne — the Daedalus Forest Evolution Engine** and says it will
replace "the current Best-of-N test runner"
(`docs/adrs/009-ariadne-forest-evolution-engine.md:9-11`). Two questions had to be
answered before that replacement could be scheduled: is the thing being replaced
alive, and does the closed Lane A2 ceiling bound the replacement? Both were
measured. Neither answer was the expected one.

---

## Finding 1 — the Best-of-N runner is not a runner, and its fitness function has never run

**It is an island.** `daedalus/kairos/evolution.py` and its only dependency
`daedalus/kairos/shadow_shell.py` are both listed under `islands` *and* under
`test_only` in the generated map (`docs/architecture-state.json`, `islands` /
`test_only` arrays — generated by `daedalus.mapping.drift`, not hand-written).
The inventory says the same in prose: `docs/FEATURE_INVENTORY.json:1274` —
`"daedalus/kairos/evolution.py (Best-of-N runner; also the explicit baseline; no
CLI/API caller)"`. MEASURED: a repo-wide grep for the three public methods
returns their definitions plus `tests/test_kairos_evolution.py` and nothing else.

**It has no pipeline.** `EvolutionaryOrchestrator` defines exactly `__init__`,
`generate_candidates`, `evaluate_candidates`, and `select_best`
(`daedalus/kairos/evolution.py:19,22,45,84`). There is no method that chains
generate → evaluate → select. The "runner" is three disconnected callables.

**Its fitness function has zero callers — including its own tests.** MEASURED:
`evaluate_candidates` appears in the repository exactly once, at its definition
(`daedalus/kairos/evolution.py:45`). `tests/test_kairos_evolution.py` exercises
`generate_candidates` (line 74) and `select_best` (lines 88, 103) against
`MagicMock` worktrees and a `DummyAdapter`. The only part of the module that
decides anything has never been executed by anything.

**And if it were called, it would score the wrong code.** This is the load-bearing
measurement. `evaluate_candidates` shells out to a **bare** `pytest` with the
candidate worktree as cwd:

```python
# daedalus/kairos/evolution.py:56-62
process = await asyncio.create_subprocess_exec(
    "pytest",
    cwd=str(candidate.worktree_path),
    ...
)
stdout, stderr = await process.communicate()
```

Bare `pytest` — unlike `python -m pytest` — does **not** put the working
directory on `sys.path`. MEASURED, in a directory shaped exactly like this
repo's checkout (no `tests/__init__.py`, no `conftest.py` anywhere, no
`[tool.pytest]` section — all three verified absent):

```text
CWD = ...\scratchpad\fakewt
CWD ON sys.path? False
  path: ...\fakewt\tests          <- sys.path[0] is the TEST dir, not the worktree
  path: ...\Scripts\pytest.exe
  path: ...python310.zip
```

`daedalus` is installed editable, and the editable finder pins the package to the
primary checkout by absolute path:

```text
# site-packages/__editable___daedalus_0_1_0_finder.py:9
MAPPING: dict[str, str] = {'daedalus': 'C:\\Users\\nukei\\Desktop\\agent_env\\daedalus'}
```

So MEASURED, with a candidate worktree carrying its own marked `daedalus/`:

| invocation | `daedalus.__file__` resolves to | candidate's code seen? |
| --- | --- | --- |
| `pytest` (what evolution.py:57 calls) | `C:\Users\nukei\Desktop\agent_env\daedalus\__init__.py` | **No** |
| `python -m pytest` | `...\fakewt\daedalus\__init__.py` | Yes |

pytest still *collects* the candidate's `tests/` (cwd-rooted), so the runner would
execute **the candidate's tests against the primary checkout's code** — a
split-brain evaluation in which the candidate's actual change is never run. The
score is therefore constant with respect to the candidate.

Both horns are closed. If `daedalus` were *not* installed, the worktree still
would not be on `sys.path`, `import daedalus` would raise, every candidate would
score `0.0`, and `select_best` would return `None`
(`daedalus/kairos/evolution.py:91-96`). ASSUMED for the uninstalled case — the
mechanism is measured, the uninstalled configuration was not constructed.

**The selection is a filter, not a ranker.** Scores are only ever `100.0`, `0.0`,
or `-1.0` (`evolution.py:51,64-67,72,75`). `select_best` keeps `score >= 100.0`
then applies a stable sort over a single distinct value
(`evolution.py:91-102`), so input order decides. Best-of-N here means
**first-green-wins**. (`evolution.py:101` also assigns `best` and then returns
`valid[0]` instead — harmless, but nobody has ever read this function closely.)

**Verdict on question 1: the Best-of-N runner is dead, and it does not work.**
Its single commit is `b2de339`. It has never been wired, never been called, its
fitness function has never been tested, and the fitness function is broken in a
way that makes its output independent of the thing it scores. ADR-009's premise —
that Ariadne replaces a working baseline — is false. There is no baseline.

**Cost to run today.** The fitness signal is one full suite per candidate.
MEASURED 2026-07-29: collection alone is 5.84 s for 2063 tests; a full run is
**2064 passed, 1 skipped, 35 subtests in 576.41 s (9 min 36 s)**. Provenance
caveat, because this repo does not time under load: that run overlapped a
duplicate suite run, so 576 s is an UPPER bound, not a clean figure. An
uncontended re-run was attempted and killed by a harness timeout at 74%, so the
clean figure is unmeasured; the load-bearing fact — **order of ten minutes per
candidate** — is not in doubt either way.
Best-of-N with population N costs N of those, and
`asyncio.gather` (`evolution.py:80`) waits for all of them with **no timeout** on
`communicate()` — one non-terminating candidate test blocks the generation
forever. Disk is not the constraint: a worktree checkout is 440 tracked files /
5.5 MB (MEASURED), against 2.89 GiB free on `C:` (MEASURED 2026-07-29; the master
plan's §3.3.4 figure of ~0.57 GiB on 2026-07-28 has since eased).

## Finding 2 — the 2.3% ceiling does not bound Ariadne

Established from the source, not from authority.

**What it measured.** `daedalus/eval/ceiling.py:1-13`: for each *missed
`must_include` label* in the `independent_diff` eval corpus, is any in-scope file
defining that symbol a **co-change partner** of the task's focus file at all?
It is the upper bound on what a temporal co-change tier could add **to the
context slicer's retrieval**. It is not a measurement of code quality, candidate
quality, or anything evolutionary.

**The number, MEASURED — re-run for this ADR, not accepted on authority.**
`python -m daedalus.eval.ceiling --min-count 2`, 2026-07-29:

```text
min_count=2  miss_tasks=7  missed_labels=43  excluded_tasks=0

  CLEAN arm (history strictly before each mint): {'NO_INSCOPE_DEF': 1, 'REACHABLE': 1, 'UNREACHABLE': 41}
  LEAKY arm (full history, incl. the mint commit): {'NO_INSCOPE_DEF': 1, 'REACHABLE': 6, 'UNREACHABLE': 36}

  clean ceiling: 2.3%   leaky ceiling: 14.0%

  clean-arm REACHABLE labels (audit these -- each is a claim that pre-mint history named the file):
    mint-commit-b1e7bf80890a  _dispatch

  reopen signal: none -- 1 clean-reachable label(s) in 1 task(s) is below the
  materiality floor (floor: >= 10% of scored labels or >= 3 tasks); the
  temporal lane stays closed.
```

This reproduces `daedalus/eval/ceiling.py:45-59` exactly, down to the single
recoverable label (`_dispatch`, the genuine verifier↔ollama coupling crossing
the rebrand): 7 miss tasks / 43 missed labels, clean rename-aware ceiling
**1/43 = 2.3%**, leaky arm 6/43 = 14.0%. The docstring's structural context also
holds: **41 of 43 missed labels are UNREACHABLE on the clean arm**, sitting on
focus files born at their mint commit, so their unreachability is structural
under any enrichment. The reopen signal is negative and prints its own inputs.

**The instrument is sound.** `tests/test_temporal_ceiling.py:3-13` carries a
POSITIVE control (a fixture that must be counted `REACHABLE`, which a
always-report-zero bug would fail) and an ARTIFACT control (clean arm
`UNREACHABLE` while leaky says `REACHABLE`). The module also self-reports
degraded runs rather than printing an authoritative zero
(`ceiling.py:158-192, 408-411`). The docstring records that the *first* version
of this check was rename-blind and published a claim that an adversarial pass
then refuted (`ceiling.py:32-43`) — the number in the file is the corrected one.

**Scope of the close.** The reopen gate is machine-stated:
`REOPEN_MIN_SHARE = 0.10`, `REOPEN_MIN_TASKS = 3`
(`daedalus/eval/ceiling.py:117-118`), evaluated at `ceiling.py:353-354`. The
docstring explicitly narrows the conclusion: *"slice-side co-change enrichment
was NOT built (design NO-GO'd on this measurement)"* (`ceiling.py:56-59`), and
warns the zero "generalizes weakly" (`ceiling.py:66-69`).

**Answer: it bounds only the lane that was closed.** Lane A2 is one candidate
enrichment tier for the context slicer. The ceiling says nothing about
evolutionary search over code, and citing "2.3%" as a bound on Ariadne would be a
category error. `ceiling.py:27-30` pre-emptively forbids the adjacent
misreading — *"Never report this ceiling as slicer recall"* — and the same
discipline applies here. **Lane A2 stays closed on its own merits; Ariadne is not
gated by it.**

## Finding 3 — neither available fitness signal can carry an evolution engine

This is the central question, and the answer is that the signal does not exist.

### 3a. "Tests pass" is measured worthless here

Not an opinion in this repo — a measurement.

- **18 of 61 mutants survive.** INHERITED, `docs/archive/2026-07/HANDOFF.md:699-703`: *"of 61
  mutants (final count), 18 guards survive their own deletion. Three times in one
  day a fully green suite sat over a live escape. That is now a measured property
  of this repo's tests, and it is the reason `tests pass` cannot be the fitness
  signal for the self-improvement loop."*
- **The three escapes, itemised.** INHERITED, `docs/archive/2026-07/HANDOFF.md:495-497`: *"29
  green over a live repo deletion, 68 green over an out-of-tree delete reported
  as success, 121 green over seven gate bypasses."*
- **A silently dropped task under a green suite.** INHERITED,
  `tools/self_test.py:177-179` and `tests/test_bridge_signals.py:230-232`: a task
  queue that drops a task when two arrive in the same second, *"Found by the
  acceptance run, not by any unit test -- 1753 of them were green over it."*
  (Provenance note: `.room/room.md:740` states 1756 for the same incident. The
  two in-code sources agree on 1753; the discrepancy is unresolved and neither
  number was re-measured for this ADR.)
- **The standing warning.** INHERITED, `docs/archive/2026-07/HANDOFF.md:757-760`: *"Fitness
  signal warning, now MEASURED and not an opinion: `tests pass` is worthless as a
  promotion criterion here."*
- **Already a quarantined claim.** `docs/archive/2026-07/HANDOFF.md:1183` lists
  *"candidate-authored tests used as sole correctness proof"* among claims that
  may not be restored without an independent benchmark.

An engine that selects on this signal is the AlphaEvolve-clone failure mode by
construction: candidates passing their own tests.

### 3b. The eval corpus cannot serve either

- **It is ADVISORY by explicit guardrail.** `daedalus/eval/harness.py:816-818`:
  *"GUARDRAIL: this gate is ADVISORY ONLY... It must never be wired to block an
  autonomous action."* Repeated at `harness.py:32-36`, `daedalus/eval/__main__.py:8-9`,
  and `daedalus/eval/baseline.json:2`.
- **It measures retrieval, not correctness.** A task's score is recall of
  `must_include` symbols in a context slice (`daedalus/eval/tasks.py:10-21`).
  Nothing in it evaluates whether a code change is good.
- **The gradable tier is saturated, and self-graded.** MEASURED by reading
  `daedalus/eval/baseline.json`: 10 tasks, every one `tier: primary`,
  `label_provenance: hand_reachable`, `recall: 1.0`. A signal already at its
  maximum has no headroom for a selector to climb. Worse, the tier's provenance
  is its own: `docs/archive/2026-07/HANDOFF.md:1461-1466` records the 100% as *"explicitly
  labelled PARTIALLY SELF-GRADED"* — the labels were derived from what the
  slicer could reach.
- **The rest is quarantined by construction.** 17 minted tasks, all
  `tier: quarantine`, all `confirmations: 0` against `MINT_CONFIRM_THRESHOLD = 3`
  (`daedalus/eval/mint.py:185-195`); `harness.py:254-256` keeps quarantine
  *"never inside a go/no-go figure"*. `docs/architecture-narrative.md:160` states
  the consequence plainly: the 86.2% *"appears in every render and in no go/no-go
  number by construction."*

### 3c. The one adjacent precedent that works

`tools/self_test.py` is the right shape and proves the method is available here:
it seeds one real defect per acceptance check into a disposable clone and
requires that check to go red, reporting `UNFALSIFIABLE` and exiting non-zero
when nobody catches it (`tools/self_test.py:1-33`). It covers 15 of the 17
checks in `tools/system_check.py`, with the 2 gaps named and justified
(`self_test.py:276-283`). `runs/ab/oracle_check.py:1-20` applies the same rule to
the A/B scorer, after the first A/B produced *"two implementations that passed
the gate, scored an identical 21/23, and contained no tests at all."*

MEASURED: **none of the 17 acceptance checks covers evolution, candidates, or
fitness** (enumerated from `system_check.CHECKS`; grep for
`evolution|fitness|best.of.n` across both tools returns nothing). The instrument
exists; it has never been pointed at the thing Ariadne would depend on.

## The preconditions

Each is stated as a property, the evidence that it is currently unmet, and a
**falsifiable check** — something that can go red — that would show it satisfied.
P1–P5 are blocking. P6–P9 are required but are engineering and protocol, not
epistemics, and should not be confused with the blocker.

### P1 — the evaluator must execute the candidate's code

*Unmet.* Measured in Finding 1: bare `pytest` resolves `daedalus` to the primary
checkout; the candidate's change is never run.

**Check.** Build two candidates from the same base: one unmodified, one with a
seeded defect in a function the corpus exercises. Require their scores to
**differ**. Equal scores prove the evaluator is not reading the candidate. This
check is cheap, needs no model, and would have caught the defect on day one.
(A regression control for the underlying mechanism is checked in as
`tests/test_evolution_baseline.py`, together with a `xfail(strict=True)` marker
that turns the suite red the day `evolution.py` is fixed, forcing this ADR to be
revisited.)

### P2 — the evaluator must be outside the candidate's reach

*Unmet, structurally.* `ShadowShellManager.run_task` commits **whatever the agent
changed** in the worktree (`daedalus/kairos/shadow_shell.py:70-77`), and the
worktree contains `tests/`. `evaluate_candidates` then runs that same tree's
tests with no filter and no allowlist (MEASURED: grep for any test-protection
guard in either file returns nothing). ADR-009 already requires this —
*"Ariadne ... does not control its own frozen evaluators"*
(`docs/adrs/009-ariadne-forest-evolution-engine.md:26-27`) — and the master plan
records it as absent: *"Evaluator und Kandidat sind nicht durch eine externe
Root-of-Trust-Grenze getrennt"* (`docs/IKARUS_ARIADNE_MASTER_PLAN.md`, §3.2).

**Check.** Submit a candidate whose diff deletes or weakens the test that guards
the property under evaluation. Require its score to **fall, not rise**. An
evaluator that rewards test deletion is disqualified.

### P3 — the evaluator's falsification power must be measured, and published with the score

*Unmet.* 18 of 61 guards survive their own deletion (§3a). A suite with an
unmeasured kill rate is a claim, not a control, and this repo has three same-day
counterexamples.

**Check.** A mutation set over the code region under evolution, run as an
instrument on the `tools/self_test.py` pattern: every seeded defect must be
killed by the evaluator bundle, and survivors must be reported as
`UNFALSIFIABLE` with a non-zero exit. Ariadne may select only on an evaluator
whose kill rate is measured, current, and attached to the score. A kill rate is
not a one-off; it decays as the tree changes.

### P4 — the signal must rank, not merely admit

*Unmet.* The baseline's fitness is binary and its selection is first-green-wins
(Finding 1, pinned in `tests/test_evolution_baseline.py`). The one non-binary
signal available — eval recall — is saturated at 1.0 on every gradable task
(§3b). There is currently nothing for a selector to climb.

**Check.** On a held-out task set, the signal must produce more than one distinct
value across candidates **and** its ordering must agree better than chance with
an independent adversarial judgement on a labelled set. If the signal cannot
separate a known-better candidate from a known-worse one, multi-objective
selection and Quality-Diversity archives are premature.

### P5 — the corpus must have headroom and be decontaminated

*Unmet.* 10 gradable tasks at 100% recall, 17 quarantined at 0 confirmations
(§3b). Separately, `ceiling.py:15-25` documents the exact contamination failure
mode already found once in this repo — a corpus that lets the system "predict" a
commit from that same commit's own data — and shows the fix (a backtest-clean
arm computed strictly before the mint).

**Check.** The baseline arm must score **below** the ceiling of the metric, or
there is no room to demonstrate improvement. Held-out tasks must be minted from
commits the candidate generator cannot see, and the leaky/clean gap must be
computed and reported, as `ceiling.py` already does for Lane A2.

### P6 — budget accounting and guaranteed termination

*Unmet.* No timeout on `communicate()` (`evolution.py:62`) inside an unbounded
`asyncio.gather` (`evolution.py:80`). The master plan lists the same gap:
*"ohne Archiv, Lineage, Timeout, geschützte Evaluatoren oder Mehrfachmessung"*
(§3.3.5). ADR-009 requires budget accounting before the engine may be called
implemented (`009:31-34`).

**Check.** Submit a candidate whose test suite never terminates. Require the
generation to complete within its stated budget, that candidate to be scored as
failed, and its worktree to be reclaimed.

### P7 — a promotion boundary the candidate cannot cross

*Unmet as a control.* The class docstring already disclaims it — *"not a
promotion boundary"* (`evolution.py:15-18`) — and `select_best` returns a branch
with no transactional promotion path. The precedent exists elsewhere:
`safety.picker_cannot_apply` is an acceptance check with a seeded mutation
(`tools/self_test.py:266-267`). Nothing equivalent guards evolution.

**Check.** Attempt a promotion from inside a candidate. Require refusal, and
require the refusal to be a check that has been seen to go red.

### P8 — persistent lineage and archive (the Grove)

*Unmet, and correctly deprioritised.* `docs/IKARUS_ARIADNE_MASTER_PLAN.md` §3.2:
*"es gibt kein Archiv, keine Generationen, keine Lineage und keine echte
Multi-Objective-Selektion."* This is the most visible gap and the **least
important** one. An archive of candidates ranked by an untrustworthy signal is a
faster way to accumulate wrong answers.

**Check.** Deterministic `candidate_id` over (base, canonical patch, generator,
mutation config) as the master plan specifies, stable across restarts; the
archive survives a process kill mid-generation with no orphaned worktrees.

### P9 — the comparison protocol must be run once before any claim

*Unmet.* ADR-009 requires *"equal-budget, multi-seed held-out comparisons against
Best-of-N and an AlphaEvolve-style archive/island baseline"* (`009:33-36`).
Finding 1 removes the Best-of-N arm: there is no working baseline to compare
against. `docs/EXPERIMENT_A_B.md` is pre-registered but **"designed, not run."**

**Check.** Run the pre-registered protocol end-to-end on a decoy task whose
answer is already known, and confirm it reproduces the known answer. A protocol
that has never been executed is not a protocol.

## Decision

**Do not build Ariadne yet.** Build the fitness signal, and measure it the way
this repo measures every other guard — by making it go red on a known-bad input.

The ordering follows from the findings, not from taste:

1. **P1 + P2 first**, because they are cheap and because an evaluator that does
   not read the candidate, or that the candidate can edit, makes every later
   number meaningless.
2. **P3 + P4 next**: a measured kill rate and a signal with a gradient. This is
   the actual blocker and the actual work.
3. **P5** in parallel — corpus headroom is a data problem, not a code problem.
4. **P6–P9** when there is something worth spending a budget on.

If P1–P4 hold, Ariadne becomes a reasonable engineering project. Until then, the
Grove, lineage, island models, and multi-objective selection are elaborations on
a number that does not mean anything.

**Do not repair `daedalus/kairos/evolution.py` into the baseline.** ADR-009 asks
for a comparison against Best-of-N; what exists is not one and never was. Either
write a Best-of-N baseline deliberately, as an instrument, with P1–P3 satisfied —
or delete the island and stop citing it as a baseline in ADR-009,
`docs/archive/2026-07/HANDOFF.md:1157-1167`, and `docs/FEATURE_INVENTORY.json:1274`. The current
state, where three files describe a baseline that has never executed, is the
"confident prose with no control behind it" failure this repo keeps finding.

## What I could not measure, stated rather than asserted

- **The runner was never executed end-to-end.** It has no orchestrating method
  and needs a live adapter and model. Finding 1's conclusion rests on the
  measured `sys.path` mechanism and the measured editable-finder mapping, not on
  a live Best-of-N run.
- **The uninstalled-package horn is reasoned, not constructed.** `pytest` itself
  lives in the same user site-packages, so disabling it to test that
  configuration disables the runner too.
- **The ceiling was re-run and reproduced exactly**, so Finding 2 is not taken on
  authority. What that run does *not* establish is whether the corpus has grown
  enough for the reopen caveat at `ceiling.py:66-69` to matter — it is the same
  27-task corpus as the 2026-07-21 close.
- **"18 of 61 guards survive" is INHERITED**, from `docs/archive/2026-07/HANDOFF.md:699-700`.
  That mutation run targeted the worktree deletion paths; `tools/self_test.py`
  is a *different* instrument covering acceptance checks. No standing
  mutation-testing tool reproduces the 61-mutant number today.
- **Whether a live model would actually game the signal is untested.** No
  candidate generation was run. The argument that it would is structural (P2),
  not empirical.
- **The 1753 / 1756 discrepancy** in the dropped-task incident is unresolved.
- **The suite wall-clock is an upper bound, not a clean timing** — see "Cost to
  run today". The uncontended re-run did not finish inside its budget.
- **Other agents were editing this tree during the measurements.** Collection
  reported 2063 tests early in the session and 2065 later; nothing here depends
  on the exact count, but it is not a still repository.
